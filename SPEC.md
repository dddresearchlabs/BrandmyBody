# BrandmyBody
Your brand, on my body.
One landing page. 10 spots. Live auction. Stripe 20% deposit.
Site name: **Brand my Body**. Never call it Brand My Shirt, Brand My Mac, or Brand My X.
## Promise
Brands bid on logo spots on my body. Winning logos are printed as ink tattoo and shown in person and in photos. A spot is paid placement, not an endorsement, and not a promise of impressions. There will be a video of the tattoo being placed
## Rules
- Bid must beat current by $25 (min next = current + $25 / 2500 cents)
- 20% deposit due now, refunded if outbid or listing removed
- Bid invisible until paid + logo approved
- Bid in last 10 minutes extends close by 10 minutes
- Highest bid at close wins even if goal missed
- Remaining 80% charged after close (7-day Payment Link). Platform takes 10% of the winning bid only, from that payment. Outbid bids are not charged.
- Logo can be anything as long as it's not offensive; admin can refuse any bid
- Placements are worn for the listing’s `wear_months` (1, 3, 6, 9, 12, 18, or 24 months). Copy is “worn for 6 months”. Home demo stays 12 months.

## Marketplace
People list their own bodies. The original single-body demo stays at `/`. Stripe Connect Accounts v2 (Express dashboard, recipient, test keys only) for logged-in listers.
- Auth: Supabase email magic link. `/login` emails a link and accepts the 6-digit code for tests. `/logout` signs out. `/auth/callback` exchanges the PKCE `code` for a session and sets auth cookies on the redirect (`@supabase/ssr` `getAll`/`setAll`). Default after success is `/account`. Exchange errors show on `/login` (no secrets). Add `http://localhost:3000/auth/callback` and the production `/auth/callback` URL to the Supabase Auth redirect allow list (no query string).
- `/list` and `/connect` require a logged-in user.
- `/connect` — create a Stripe Accounts v2 connected account (`POST /v2/core/accounts`) or reuse this user’s `stripe_account_id`. Marketplace recipient + Express dashboard, test mode only. Create a v2 Account Link and redirect to Stripe onboarding. Return URL `/connect/callback` retrieves the v2 account (reject live mode), then saves `stripe_account_id` and sets `charges_enabled` when `configuration.recipient.capabilities.stripe_balance.stripe_transfers.status` is `active`. Stripe API errors show in the UI (no secrets). SQL: `supabase/stripe-connect.sql`.
- `/list` — create a listing: display name, optional Front photo, optional Back photo, socials (X, Instagram, TikTok, website), entire body or selected parts, starting prices, Wear for (required: 1 / 3 / 6 / 9 / 12 / 18 / 24 months, stored as `wearMonths` / `listings.wear_months`), auction length. Photos are not required to publish. New rows set `owner_id` from the session. No backfill.
- Auction length: 1 day / 3 days / 1 week / 2 weeks, stored as `durationDays`: 1 | 3 | 7 | 14. On create, `endsAt` = now + durationDays
- Selected parts use the 10 SPEC spots
- Entire body: one starting price on all 10 spots
- `/browse` — public grid of live listings (`status = live`: name, socials, spot count, min starting price, time left). Filter chips: 1 day / 3 days / 1 week / 2 weeks / all. Cards link to `/b/[id]`. Empty state if none. Removed listings are not shown. Supabase errors show in the UI (no secrets).
- `/b/[id]` — public listing page cloned from the demo landing, with that person's spots, live bids (current amount + brand), socials, wear time from `wear_months`, and time left from `endsAt`. After `endsAt`, listing is closed and Get a spot is disabled/hidden. If the lister is not `charges_enabled`, Get a spot shows “Lister has not connected payouts” and does not start Checkout. `status = removed` → “This listing was removed”. Missing listing → 404. Supabase errors show in the UI.
- `/account` — listings where `owner_id` is the current user, with time left from `endsAt` and closed after end. The signed-in email (or `user_metadata` name) is the account name: shown under the Account heading and in the site nav next to Account / Log out. Live listings with a live bid have “Remove listing” (refunds live deposits). Live listings with zero live bids have “Close early” (`POST /api/listings/[id]/close`, owner): the listing comes down, nothing to invoice. If the signed-in email is in `ADMIN_EMAILS` (comma-separated, server-only), `/account` shows an Admin pill, “Close auction” on the user’s own live listings, and every live listing with “Admin remove” and “Close auction” (same close API, `{ admin: true }`, any time). Shows Connect status: not started / pending / ready. Requires login.
- Remove listing: set `listings.status = removed`, `removed_at = now()`, `removed_by = user|admin`. For each `listing_bids` row with `status = live`, `refunded_at` null, and a Stripe PaymentIntent or Checkout session: refund the test-mode deposit, then `status = refunded`, `refunded_at = now()`. Do not refund outbid or already-refunded rows. Stripe refund errors show in the UI (no secrets). SQL: `supabase/listing-remove.sql`. Keep Connect. Test keys only (`sk_test_`).
Store: Supabase tables `listings` (`owner_id` uuid → `auth.users`, `stripe_account_id`, `charges_enabled`, `wear_months`, `photo_url`, `photo_back_url`, `removed_at`, `removed_by`, `closed_at`, `closed_by`), `lister_accounts` (`user_id` → `auth.users`), `listing_spots`, `listing_bids` (`bidder_message` optional, max 500). Types in `src/lib/listings.ts`. Server access in `src/lib/listings-db.ts` via the service-role client. Writes stay in API routes and check the user (`POST /api/listings` creates listing + spots with `owner_id`; `POST /api/listings/[id]/remove` sets `status = removed` and refunds live deposits; `POST /api/listings/[id]/close` closes now for admin (winners + 80% Payment Links) or owner with zero live bids; `GET /api/cron/close-listings` closes after `ends_at` with the same winner path; loading `/b/[id]` or `/account` after `ends_at` also closes with that path; `POST /api/checkout/complete` inserts `listing_bids` from paid Stripe session metadata). RLS: anon/authenticated can read live and closed listings; only the owner can insert/update their rows. SQL: `supabase/listings-auth.sql`, `supabase/stripe-connect.sql`, `supabase/listing-wear-photos.sql`, `supabase/listing-remove.sql`, `supabase/listing-close.sql`, `supabase/listing-bid-message.sql`. Never write `data/listings.json`. No mkdir `/var/task/data`.
Checkout: Stripe test mode on `/` and `/b/[id]` Get a spot. Deposit is 20% of the bid (Stripe’s 50-cent charge minimum is applied silently if ever needed). No platform fee on the deposit. Marketplace deposits stay on the platform so outbid / remove-listing refunds are a full PaymentIntent refund. `success_url` is `/success?session_id={CHECKOUT_SESSION_ID}`. `/success` POSTs to `/api/checkout/complete` (webhook-equivalent). If `payment_status` is `paid` and the bid is the new high for that spot: status=`live`, previous live bid status=`outbid`, refund the previous PaymentIntent (retrieved from the previous Checkout session if we only stored `stripe_session_id`), store `stripe_payment_intent_id` and `refunded_at`. Never refund the bid that just paid. If the refund fails, the new bid stays live and `/account` shows a non-secret error for the lister. Bid table Current is the live amount + winning brand; outbid rows are not current. Home auction: mock `src/lib/auction-store.ts` (`data/auction.json`, in-memory fallback if the file is not writable). Platform Checkout only (no Connect destination). Marketplace `/b/[id]`: if the lister is not `charges_enabled`, Get a spot shows “Lister has not connected payouts” and does not start Checkout. Unpaid sessions do not write a bid. Session metadata: `kind` (`deposit` or `balance`), `listingId` (`home` or listing id), `spotId`, `durationDays`, `wearMonths`, `listerSocials`, `buyerSocials`, `bidCents`, `brandName`, `bidderMessage` (optional, max 500), `bidId` (balance only). Get a spot has an optional Message box; stored as `listing_bids.bidder_message` and shown on `/account` for the lister. Checkout product description uses that listing’s wear copy (`worn for 6 months`); home demo is 12 months. Min next = current + $25. Body map FRONT/BACK panels use the silhouette and numbered spots only. Listing photos are not the map background. Winning logo still draws on the spot. No live Stripe keys.
Close: admin (`ADMIN_EMAILS`) “Close auction” on any live listing now (`POST /api/listings/[id]/close`, `{ admin: true }`). Live high bids win. Remaining 80% Payment Link with `application_fee_amount` = 10% of each winning `bidCents`; the 20% deposit stays (no extra fee, no transfer). Outbid bids are not charged. Owner “Close early” only if there are zero live bids (listing comes down, nothing to invoice). When `ends_at` passes, the same winner + Payment Link path runs from `/b/[id]`, `/account`, checkout, or daily cron `GET /api/cron/close-listings` (`CRON_SECRET`). Hobby cron is once per day at 00:00 UTC; visiting the listing or Account after time is up closes immediately. `/account` shows the Payment Link (prefilled with the winner’s email). Paying it records `balance_paid_at` via `/api/checkout/complete` (`metadata.kind=balance`). Then `listings.status = closed` (`closed_by` = `admin` | `owner` | `cron`). SQL: `supabase/listing-close.sql`. Test keys only (`sk_test_`).
Anti-snipe: a paid bid in the last 10 minutes of `ends_at` sets `ends_at` = now + 10 minutes (`listings.ends_at` for marketplace, home demo auction `endsAt`). `/`, `/b/[id]`, and `/browse` use the updated `endsAt` after refresh. SQL: `supabase/listing-bids-outbid.sql`.
Photos: `/list` optional Front photo (`photo_url`) and optional Back photo (`photo_back_url`) upload to the public `listing-photos` bucket via `POST /api/uploads/listing-photo` (service role, `view=front|back`). Photos are not required to publish. Front photo is shown on `/browse` cards. On `/b/[id]`, listing photos sit under “Your brand, on my body.” Click a photo to open a larger lightbox; click the backdrop or X to close. Photos are not bid targets and are not used as the spot-map background. Get a spot logo uploads to the public `logos` bucket via `POST /api/uploads/logo` after paid Checkout; `logo_url` is saved on `listing_bids` and home bids. Upload errors show in the UI (no secrets). SQL: `supabase/listing-photos.sql`, `supabase/listing-wear-photos.sql`.
